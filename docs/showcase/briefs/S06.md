# S06 执行卡：舰艇运动、编队与程序指挥官

本卡由统筹准备，独立聊天接单后执行。覆盖 T18–T20，直接落实用户“程序指挥官模拟真人下大指令，后续真人沿用入口”的要求。依赖 S01、四型舰艇正式定义和 S04／S05 接口；不造模型、不重写飞行／武器系统、不制作最终 UI。

接单读取 `docs/runtime-contracts.md`、`docs/combat-contracts.md`、`docs/aircraft-contracts.md` 与对应最终交付。S04 已提供 `AircraftSuite.install(world)` 及六种高层任务，航空自由飞行原点与旧地面查看器不同；不再次制作航空任务分发。高层命令的来源／意图与内部 `SET_TARGET` 区分，UI 的指挥时间线只呈现前者及真实执行变化。

## 任务与行为

- 舰艇航点、有限航速／加减速／回转、邻舰和岸线避碰，伤情影响动力／操舵。运动连续，不瞬转／瞬移；避碰应有稳定让行选择，不能长期左右抖动。
- 按 S05 最终伤情契约区分失能与沉没。`disabled` 军舰已经不再执行任务／射击，仍浮在水面；运动模块可保留有界惯性减速，不能仅因 active=false 就瞬间停住。`sinking/crashing` 位移交 S05，避免两个模块同时移动残骸；战报不能把失能直接说成击沉。
- 舰队巡航、核心舰保护、防空掩护、炮战展开、撤退及旗舰接替。通过真实航行形成队形，容许掉队和重组；不是固定相对坐标阵列。
- 对海接敌考虑射程、舷侧射界、航向和安全间隔；把目标／射击意图交 S05，不能直接命中或扣伤害。驱逐舰鱼雷只保留模型，不伪装已接入鱼雷战术。
- `ship` 域执行器使用统一高层命令。每 tick 查询当前归属，逐成员报告实际阶段和终态；部分改派不停止其他成员，取消后不再受旧任务控制。目标失联按最后接触搜索／重新部署，目标消灭或自身条件改变有可解释的结果。

## 指挥官必须像真人发任务

程序指挥官只消费 `commander_snapshot(faction_id)` 与 S05 情报；禁止读观众全知快照或直接循环敌方实时位置决策。自己的舰队状态、油弹／伤情、己方接触及当前命令决定巡逻、保护、拦截、对海接敌、集结与撤退。

意图通过 `BattleOrder`／`submit_order` 下达，复用人类相同校验和分派入口。指挥官不直接写位置、炮位、库存、伤害或低层行为状态。高层决策采用合理周期、冷却／变化条件，不能把每次转向／点射刷成新指令。

航空高层指令交 S04 执行器；不在本板块重新实现双机／四机。兼顾舰艇和航空任务：可有部分保护、部分拦截，不把每个接触都变成全军追击。损失旗舰、低油／无弹、严重损伤、失联／目标消灭后均有后续选择，原因可供 UI 解释。

记录意图、受令编队／单位、仿真时间、实际执行阶段与终态。展示文案可由 S07 翻译原因码，不能由 S06 写“正在齐射”等与行为无关的台词。完整规范见 `docs/showcase/command-and-observer-ui.md`。

## 验收与所有权

测试有限转弯与速度变化、相向／交叉避碰、慢舰掉队重组、旗舰损失接替、主力舰展开、不同损伤影响航行；指挥官相同己方情报输入得到相同决定，改变未知敌军真实状态不应影响决策。至少一条命令可追踪到实际航迹／编队变化和终态；人类来源的同类型命令走同路径且无第二套执行逻辑。

主要修改 `scripts/simulation/ship_motion/`、`scripts/behaviors/fleet_formations/`、`scripts/command/commander/`、对应参数／测试／资料及自己的交付。只通过冻结接口调用 S04/S05；共享契约变更先由统筹指定所有者。测试全部经 `tools/verify.py --owner S06`，单引擎锁、超时和清理；优先 headless，不提前开浏览器。

交付 `docs/showcase/deliveries/S06.md`，包含真实场景轨迹／命令时间线、机制验证命令与退出码、接口／原因码、剩余项及资源清理。统筹独立验收后才能作为正式指挥来源交 S07。
