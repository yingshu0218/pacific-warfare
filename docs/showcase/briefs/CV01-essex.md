# CV01 USS Essex 航母模型与甲板接口

用户授权美日各一艘航母。美国舰沿现有单位规划采用 USS Essex CV-9，拟1944年短舰艏配置；资料任务先固定可被照片支持的具体日期。按 `docs/showcase/expansion-plan.md` 执行，统筹指定启动后才开始；独立 Sol6.1 max 聊天，不创建下级代理/聊天。只做本舰模型与安装/使用接口，不把航空 AI 一并塞入模型生成器。

## 资料与轮廓

先读取军舰模块化/参考图规范、统一美术方向及已验收 S02/S03 模型接口。精选并实际打开同舰相近目标日期的侧面、俯视/高位、斜前后照片，核对短舰艏、飞行甲板、舰岛/烟囱、升降机、防空平台；异舰/异期图片标注不能证明的部分。不得混入战后斜角甲板或后续改装。来源目录只是线索；重要轮廓和主炮布局未知则继续查证或明确原型未核准，不伪造测量精度。

保持米制长宽、甲板外轮廓/层级、舷侧与舰岛体量，简化表面细节；机库只做外观和开口暗面，无内部机械。舰体、舰岛、真实平台/炮座、武器、升降机等分模块。主炮/高平两用炮逐座锁定型号、数量、单/双联、位置和承载；轻防空历史配置与游戏配置分表。优先复用已合格武器，缺失炮架变型只新增对应模块，不用相似模型缩放冒充。

## 所有权与共同接口

本舰专属模型/生成脚本/装配数据、明确的新武器变型、专属检视场景、资料/检查及 `docs/carrier-deck-contracts.md` 初版归 CV01。不改现有舰船、FX/DM、普通启动脚本、S14场景或航空运动。若共用武器有缺陷，记录给统筹安排，不静默改所有舰艇。

当前19单位基线仍在交付。未准入的新单位/武器/弹药定义先放本舰专属开发目录，不直接放进现有 `data/units`、`data/units/weapons`、`data/ammunition` 自动扫描目录；否则即便场景没有生成航母，半成品定义也会破坏旧场景的目录校验。正式注册由统筹协调S14扩展批次。尽量不在通用scripts目录放半成品全局class；本舰通过后再公布可打包资源边界。S14/S08冻结当前基线时配合声明本轮尚未消费的目录，不能让新研究图、模型开发日志或未完成场景进入基线Web包。

首先发布最小甲板数据，供 CV02/OPS01 共用语义：舰体局部坐标/轴/比例；飞行甲板边界与高度、障碍、起飞与着舰中心线、停放/折翼区域、升降机范围/高度/活动轴、候机与退出路径参考。数据与真实可见表面一致，随母舰世界姿态变换；美日可有不同布局。不在模型里决定排队、瞬移飞机或发出指挥命令。

模型提供舰艇现有运动/炮位适配、碰撞代理、独立武器状态、升降机/必要活动状态。整舰组装中放入真实尺寸 F6F/SB2C 检查停放、翼展、障碍和可用通道，静态摆放只算安装验证，航空作业另由 OPS01验收。不得为容纳不合理数量随意放大甲板。

## 交付与验收

模块→整舰→安装检视，侧/俯/斜视和主炮/甲板关键近景实际核对，机制核尺寸/宿主/运动独立/甲板表面一致。必要原生截图自动退出；浏览器等整舰/使用场景完成后再调度，不反复开浏览器建模。核对简化后的正常观战辨识，不因细栏杆/铆钉不足返工。

交付 `docs/showcase/deliveries/CV01.md`、`docs/showcase/evidence/CV01/`、已实际看过的参考卡、主炮/防空清单、甲板契约及已知近似。每个待核实项保留状态，哈希与本轮清理完整。所有 Godot/渲染/编码用 `tools/verify.py --owner CV01` 统一锁。根入口仍保留大和，独立检视不改用户默认场景。
