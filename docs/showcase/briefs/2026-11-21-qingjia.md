# 青岬归航：可玩任务与港湾帧时间

2026-11-21。依据[青岬设计](../../design/qingjia/README.md)，本轮只接第一批。普通港湾保留原有编制、默认入口与观战能力；青岬是一个单独可选的任务。现有 27 单位港湾是性能对照，不能用比较小的青岬场景替它交卷。

## QJ01 · 观众在等谁

入口用一句话告诉观众：埃塞克斯要带走本次点名的两架 F6F。登记**母舰实例、机体实例和出动身份**，从舰上作业和航行的实际状态取证。可由合法的初始任务和通用规则自然完成；不能在某秒强制起飞、返航、落舰或把船搬到终点。已有港湾、训练和单机自主空战的入口均保留。

| 要问的问题 | 验收预期 |
| --- | --- |
| 同一架先后发了两次回收回报，另一架失联 | 实际到区时最多 1/2；另一架最后可知状态和时间如实保留，不能写成已损失 |
| 两架都停在初始甲板，或者非点名飞机成功落舰 | 没有本次实际回收，不计入随舰撤出 |
| 真正落舰后又起飞，或改降他舰 | 有落舰记录也不等于在指定母舰上一起到区 |
| 回收指令被接收、母舰接到撤离令，但还没到区 | 尚未达成，不提前弹出胜负 |
| 母舰真正到区 | 指定两架均在舰为完成；0 或 1 架为部分达成，并逐架交代依据 |
| 母舰沉没或期限届满仍未到区 | 未达成，分原因；同一模拟步按可复现且公开的边界口径处理 |
| 未决时手动结束，或者结算后再按结束 | 前者中断；后者保留已经冻结的终态。重开清空上局名册和记录 |

交付小型受控案例（含时间边界、重复事件、重新出动）及至少一局正常入口或同一正式工厂的自然结果。区分自然看到的分支和仅在测试中构造的分支。普通观众能读到两架的身份、去向和结果。模拟不得依赖正在看的镜头。

## PF01 · 普通港湾为什么会卡

对相同包、种子 707、机位、1×、相同视口预热后取样。记实际设备、浏览器能见度/焦点、CSS 画布与绘图缓冲、壁钟及模拟进度，将浏览器画面间隔和引擎内部帧耗时分开。先用简单画布、游戏暂停、完整观战和可控的单变量诊断区分页面调度、模拟、3D 及 HUD；按证据决定修哪一个热点。以未经诊断改写的正式页面作最终对照，输出 p50/p95/p99 和样本量。上一版证据见[机动验收](../../deliveries/2026-11-19-aerial-motion.md)。

不能跳过模拟步、抽掉单位、炮弹或受损事件换帧率。相同种子、对齐的模拟时刻应有相同状态与事件摘要。诊断可隐藏组件测成本，不能把诊断模式冒充常规试玩。质检只用 Ego Lite；目标为 M5/16GB、真实 1440×900、1×、P95 ≤33.3ms。若达不到，给出实测和下一项最有依据的工作。

## 分工和交付

QJ01 独占任务、场景配置、菜单最小接入和运行资源登记；PF01 独占测量与经验证的热点，不改任务和界面内容。运行 Godot、导出、浏览器测量依次持有项目验证锁。统筹核对已有包、任务边界和玩家入口，负责向正式构建交付；执行聊天不可覆盖用户正在运行的包。更大规模、美术、完整 HUD 和人类指挥席分后续批次。
