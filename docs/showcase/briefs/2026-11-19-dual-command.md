# 双指挥官与舰炮分配

默认港湾中，日美每方各有一名舰队指挥官和一名航空指挥官。两者使用本方单位、任务进展与已知接触，在游戏规则内各自决定进攻、平衡或保守，并沿已有订单接口调动各自的编队。观众能看到下令人、姿态、任务及真实执行结果。

## CMD02 指挥与观战

- 舰队指挥负责舰艇，航空指挥负责空中编队及已有轰炸任务。两者可围绕同一场景目标协作。分派和换令应保留玩家已有任务、训练、甲板作业、正在脱离的单位以及既有任务的有效阶段。
- 在相同已知接触下，进攻可选择更多合法任务机会，保守优先保全可用编队或保护己方，平衡兼顾任务推进与保留力量。设计可从受控游戏状态触发各姿态的选择或切换。选择目标、空置预备队、保留／替换任务等应能观察出实际差异。使用稳定决策间隔、滞回或任务承诺，防止接触轻微变化时反复改令。
- 每个阵营的两个指挥岗位具有可追溯的签发身份。普通「指挥态势」可看双方两个岗位的当前姿态、形成原因及订单的下达、执行和结束过程。选中舰船的详情用简洁文字显示炮组及实际分配目标，读取既有 `combat_runtime.mount_targets`、`mount_status` 和各炮位角色。使用正常 HUD，保持 720p 控件可读。
- CMD02 所有权包括高层指挥、任务意图和相关发行／兼容入口、观战 HUD 及必要的只读探针。舰炮共同接口是 `world.shared_state["command_postures"][faction_id]["fleet" 或 "air"]`，至少含 `posture`。值为 `offensive`、`balanced` 或 `conservative`。建议同时提供 `reason`、`issuer_id`、`changed_tick`。旧场景缺失该记录时视为平衡。编队意图仍走 `submit_order`。

## GUN01 舰炮分配

- 舰船保持总体任务目标。主炮、副炮、两用炮、专用防空炮按现有游戏角色和受令意图在己方有效接触中分配。任务优先级、岗位姿态、可用目标数和可用炮位共同决定是否集中、分担或待命。对炮位不适用的目标应退出候选。保持既有停火、锁定指定目标、防空许可和域边界。
- 在受控混合目标场景中，同舰不同炮组能在相近时间对不同合法目标实际发射。单目标可集中。失去接触、失能、耗尽弹药、暂时无可用目标等状态能回收或改派。使用现有游戏武器执行器和库存。以真实 `fired`、炮位 ID、目标和扣弹作为验收依据，齐射记录须与当次实际发射一致。
- GUN01 所有权包括炮位目标分配、必要的齐射事件适配及其回归测试。HUD 由 CMD02 统一编辑。沿用现有武器、弹道、模型和伤害参数。

## 集成与验收

两个 GPT-6.2 Sol High 项目聊天并行实施，所有 Godot 验证经 `tools/verify.py` 串行，普通 Web 导出和 Ego Lite 由统筹负责。统筹在 `.local/repairs/20261119_dual_command/before` 保存了接手版本与包。各执行聊天提交本任务交付记录、修改文件和新增运行文件清单，统筹登记 Web 准入。

验收覆盖态势变化和目标排序、双岗位权限、三姿态的真实任务差异、无接触与状态恢复、重开一致性、炮组实际分火、原有轰炸／截击／狗斗及正常界面。默认场景采用自主规则，结果按当次运行记录。
