# S10：陆基防空与岸防炮

用户明确要求地图陆地可以安置防空炮、岸防炮。本板块与 S09 地图分开执行，依据用户对历史轮廓、武器行为和简化画面的既有要求制作真实可交战单位。独立聊天已完成历史资料/型号核对。2026-11-11，S04 v3 原生/机制及 S13 云海/Chrome 短测通过统筹复核，两个执行聊天均结束；现放开模块建模、安装与必要共享接入。保留已验收的飞行、云海、地图与现有音频稳定路径。

## 前置和所有权

S09 地形与安装点契约发布并基本通过后启动；与其他聊天最多两路并发。优先等待 S04 航空和 S09 地图集成稳定，再由 S08 对最终版本做浏览器验收。不新开下级聊天或子代理；固定引擎，所有原生/headless 通过同一互斥验证工具，结束清理。

拥有陆基单位定义、简化模块模型、任务行为及 `ground` 单位域接入；按必要范围更新 catalog 验证、指挥/目标/伤害/观战读模型，单一所有者修改共享文件。不得把岸炮伪装成零航速的军舰，或令其损毁后沉船/坠机。S09 地形和 S04 航空由原所有者处理，新问题报告统筹协调。

## 最小交付

- 至少一种有可靠资料的二战陆基/岸置防空炮和一种岸防炮。优先复用现有炮管/炮架模块，但陆上安装型式必须有依据；舰炮塔直接摆在土地上不能自动视为史实。
- 模型强调外观、炮管/炮架比例、独立水平转向和俯仰、真实炮口、混凝土/土筑承载。不做内部机械、人员、弹箱运输或精细阵地土木。
- 首次部署建议为同一驻军的 1 座岸炮＋2 座防空炮，配置可扩展；具体型号、日期、弹药与服役年代先锁定并记录来源，不为了数量对称额外造一套阵营。地名/基地是原创架空，装备资料不得混淆。
- 通过 S09 的阵地数据决定位置/朝向/阵营/装备；验证地面承载、坡度、安全半径和炮口露出。错误放置应给出可读报错，不默默悬空或塞入地面。

建模前实际打开少量合适的原始照片/图纸；按 `docs/standards/modeling-references.md` 留下外形、尺寸、变型边界与未知项。AI 风格图可选，不能替代历史结构来源。

统筹已检索到的优先调查方向是美军 5-inch/51 岸炮与陆用 40 mm Bofors M1；这只是资料入口，未完成建模参考核对或锁定子型。可先查看 [USMC《A Magnificent Fight》官方原文/照片](https://www.marines.mil/Portals/1/Publications/A%20Magnificent%20Fight_Marines%20in%20the%20battle%20for%20Wake%20Island%20%20PCN%2019000311900_2.pdf)、[NHHC 威克岛守军资料](https://www.history.navy.mil/content/history/nhhc/browse-by-topic/wars-conflicts-and-operations/world-war-ii/1941/philippines/defenders-of-wake.html) 和 [美军军械发展官方出版物](https://www.govinfo.gov/content/pkg/GOVPUB-D114-PURL-gpo84071/pdf/GOVPUB-D114-PURL-gpo84071.pdf)。不得用英国型 Bofors 照片或既有舰用四联装直接充当美国陆用 M1 的型号证明。

## 战斗和指挥

复用统一探测、己方接触、火控、旋转/俯仰、弹药库存、真实弹丸、首次碰撞和损伤。陆基防空射击飞机，岸炮射击舰艇；舰炮能在实际接触/任务许可下反击地面武器。目标域和弹种明确配置，不能通过无限射程或假命中制造效果。

岸上兵器拥有独立 id、阵营、型号、服役年、武器状态与损伤。区分工作、武器失效、摧毁/残骸，不应用舰船进水和飞机坠落逻辑；毁坏后停止索敌/射击，残骸按约定仍可遮挡。岛山和建筑实际约束射线、弹道与爆炸。

程序指挥官下达区域防空/海峡警戒/指定目标交战等真实高层命令，接收与执行仍走统一接口；具体最小命令类型可复用或扩展，先发布契约。未来真人仅替换命令来源。正常双方指挥 UI 展示驻军/炮组任务、目标、状态/受限原因、油弹中适用项（固定炮位无燃油需求，不显示虚假油量）、损伤和时间线；支持定位阵地。

S12 规划审查发现 `scripts/game/first_playable_session.gd::report()` 当前以“ship，否则 aircraft”计数，事件镜头分类和单位任务读取也存在 ship/aircraft 二分。S10 接入 ground 时一并修正这些实际域分类：陆基数量/损失独立统计，不能冒充飞机；任务字段读取和受击/射击镜头语义对应陆基。只做必要兼容，现代 UI 改版仍由后续独立实施任务负责。

不新增地面移动、部署编辑器、步兵、后勤或弹药补给玩法。场景数据配置足以完成本轮“安置”。

默认地图交战布局可以为陆上驻军合理配置舰队位置、空中巡逻区和指挥意图，确保敌机实际进入陆基防空的有限射程，双方军舰也有对岸交战机会。先测量阵地与自然航迹的距离；不要保留远离战区的炮位后仅靠加大武器射程来制造参战。优先使用已验收的低岸/港区点；高地可以暂留空位。上述调整写在新增地图场景数据，保留 `first_playable.json` 与 `showcase/open_sea.tscn` 的原四舰八机基线，明确记录布局变化。

## 验收

1. 两类真实单位已在港口/高地阵地装配；尺寸、基座、轴和炮口通过可视检查，服役/配置资料有来源。
2. 在同一地图的实际场景中展示岸炮对舰、陆基防空对空及舰艇对岸炮反击；允许使用同地图的受控机制预设覆盖难以自然出现的状态，但明确区分默认实战与受控预设。
3. 地形遮挡、火线受限、库存耗尽、转向俯仰、损毁停火、重开和不同渲染节奏均符合统一机制；不能只证明炮架会动。
4. 正常 UI 有真实指令、执行与损失/战报归类，AI 不读取全知敌情。默认场景无人工干预可发生上述交战，不为了表演偷偷改变武器参数。
5. 通过有意义的域扩展回归，旧四舰八机模型/射击/损伤和入口仍可运行；提供原生连续画面、实际单位/弹丸/绘制成本、全部自建资源清理记录。
6. 写 `docs/showcase/deliveries/S10.md` 和证据/hash，向统筹交付；S08 再统一做最新地图＋立体空战＋陆基单位的Chrome 性能、声音、10 分钟/三次重开和清理验收。
