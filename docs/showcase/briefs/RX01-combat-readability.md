# RX01 舰船损伤与真实弹道可读性修复

用户2026-11-12体验反馈：战列舰似乎两下就沉，损伤/损失过程不清楚；看不到炮弹飞行与舰队防空火力网。复用S05会话执行，统筹验收。以当前535源的expanded体验版为基线，固定引擎与简化画面范围不变。

用户随后明确这是游戏的交战节奏与角色问题，不只修“两下沉”的症状。按[交战节奏与单位作用](../combat-pacing.md)校准：比较重舰、轻舰、飞机/轰炸机的有效输出、抗打击与任务作用，分开搜索/攻击机会、命中后失能、真实沉没三段时间。总体20–40分钟沿既定完整场景目标，不强求单项片段同长；当前常规舰炮对抗要有可观赏的数分钟进退与损伤变化。允许有依据的游戏耐久与毁伤传递校准，禁止统一抬HP或改成按时间存活。至少给出常规同级、重炮对轻舰、轻炮对重舰的同条件前后对比，避免重舰/轻舰只换模型而无角色差别。

用户再补模块化规则：舰体未有效击破时不应轻易沉没；上层建筑损坏主要是功能模块失能/降效。本轮已有炮位、动力、操舵、火控要体现基本局部关系，不能仍由一个control部位损失关闭全舰。先做局部健康/效率和浮力区别，不扩展独立电网、精细逐舱损管。需要FirstPlayable/普通HUD消费模块摘要时写交接，由S14/统筹接入。

可修改 `scripts/simulation/damage/`、确有依据的战斗配置、弹丸机制及 `scripts/presentation/effects/`；新增本任务的机制检查和只读诊断。不得覆盖原冻结FX/DM证据或按旧样件整文件回滚。`scripts/game/first_playable.gd`、Session表现快照、镜头/地图/场景由并行S14所有，需要新只读接口时写交接文件，由S14/统筹接入。白名单、普通builder、最终导出由统筹收尾。

当前没有Git；540份源/配置与体验包已备份在 `.local/repairs/20261112_morning/before`，基线清单同目录baseline.json。当前源码上直接修复所辖文件，改动前确认该基线；新增文件单列。新检查/截图/中间数据优先放该修复目录。不得修改不属于本任务的源。

## 必须解决

1. 先用实际伤害事件复现普通港湾/炮战的战列舰过快失能/沉没：区分两发与两轮齐射，核实际命中部位、弹药能量、装甲、单发/爆炸是否重复结算、火灾/进水和控制损伤。现有control原因已进入disabled而非sinking，不假定该保护不存在。核查UI是否把失能等同击沉。修正源头，保留部位损伤、火灾/进水和实际失能/沉没进度，不单纯靠全局加HP或削弱敌方武器获得展示时长。缺少历史依据的近似明确记录，不能称作历史精确毁伤模型。
2. 主炮非tracer弹也须有可辨的实际飞行显示，显示与真实弹丸/弹道同步；允许观察用的短轨迹、亮点及有限视距补偿，不能画虚构命中线或改变弹速/伤害。小口径曳光、防空空爆黑烟、水柱/泡沫仍保留。
3. 用真实开火数量、可见效果数量和镜头距离判断防空不明显的原因；检查384池化预算是否挤掉曳光。若普通态势根本无防空交战，提供具体证据给S14协调合理初态/既有火力场景；禁止假火网、定时开火、无敌靶或镜头制造战果。

用同一真实命中输入证明局部损坏不会无故击沉、足够实际损伤仍可沉没，确认一次接触只结算一次。保留有限库存、首碰撞、旧飞机损伤的必要相关回归。不是新资产制作任务。
