# S11：音频制作与接入规划

用户于 2026-11-10 明确要求新建独立对话，先规划音频如何制作。本任务仅做资料核对与可执行规划，不制作正式声音、不改运行代码、不买素材、不上传项目，不启动 Godot、浏览器或预览服务。既有地图、空战和岸防任务继续按自身范围实施；音频生产需另行明确安排。

## 工作方式与上下文

读取 AGENTS.md、总体规划、当前 Showcase 计划与战斗事件契约。复核 `scripts/presentation/effects/combat_audio_bank.gd`、`combat_effects.gd`、`scripts/game/first_playable.gd`、`assets/audio/SOURCES.md`，以及 S08 音频排错/Chrome 阶段交付。只读上述运行文件。输出在本任务规划与交付文档中，向统筹报告；不创建下级会话或子代理。

首版为电影化放置观战，画面简化，但行为、弹药和命中都来自真实模拟。当前 4 舰 8 机，未来每方 20–30 舰、100 机；有岛屿、小镇、港口和即将接入的陆基防空/岸炮。模型先锁具体子型和配置，不代表音频必须逐型精确复刻。

现有声音是 11025 Hz 原创程序 PCM 占位：heavy/light/impact/engine，最多 8 个单次声源和 4 个循环声源。它们不是对应历史装备的实录。当前循环按单位遍历取前 4 个、音高按速度映射，需在规划中评估相机附近声源选择及动力状态的适用性。S08 已修复网页音频节点累积：幂等暂停控制与 Web `PLAYBACK_TYPE_STREAM`；任何未来方案不得重新引入该故障或升级固定 Godot 4.7.2 引擎。后续浏览器实测只用 Chrome。

## 规划需要解决的问题

1. **首版声音范围与优先级。** 按持续声、事件声、环境声分组；列 P0/P1/后置。P0 优先战斗机发动机/螺旋桨、舰艇近景动力、主副炮/防空炮/机枪、空爆、海面水花/陆地与舰体命中、损毁；环境是海浪和风等轻量底层。语音、配音、音乐先判断价值与成本，不自动扩成主线。
2. **素材怎样获得和制作。** 对比可商用授权实录、可复用素材加工、原创合成及 AI 辅助音效的适用范围。推荐一条首版主线和缺素材时的替代办法；查真实来源与条款、费用和可访问性。原始下载/母带/编辑工程/游戏导出/来源台账分开，给出命名与目录。不要把 AI 音效或普通发动机素材标成某历史型号的准确录音，也不提取其他游戏声音。
3. **从声音家族到具体单位。** 用少量家族覆盖现有机型/口径/弹着介质，再给有价值的近景声音留差异化入口。每个候选声音列长度、循环/单次、变化版本数、单声道/立体声、建议源格式与运行格式，以及可验收的辨识特征。数量和采样率为明确预算建议，按网页负担核对，不堆几十个没有用途的素材。
4. **真实事件接入。** 映射 fired/airburst/surface_impact/hit/damage/退出等实际事件和循环动力状态；避免重复触发、重开漏清理、每发炮弹一个无限播放器。区分枪口声、弹道掠过、爆炸和落水，不为演出生成虚假射击。暂停、倍率、结束、撤离、失效、重开必须有统一规则。
5. **电影镜头和空间听感。** 规定监听点、距离衰减、远近层次、必要传播延时/遮挡近似、多普勒适用范围、自动切镜/自由移动的平滑处理。给出主炮齐射、舰队防空火网、近距离狗斗、港口/岸炮四类听感目标。强调“听得清主事件”与距离感，不靠一律加响压满输出。
6. **混音与网页预算。** 规划总线、类别音量、近景优先级/声源抢占/虚拟化、重复声随机变体、压限和峰值余量。按当前 4+8 与未来大编制分别给出可测预算及风险；不要先承诺未经实测的并发/内存数。历史 S08 样本只作起点，最终需要 Chrome 有声连续运行、切镜、暂停/恢复、倍率/重开和声源/内存增长检查。
7. **任务拆解。** 分离素材资料包/加工、音频系统接入、场景混音、Chrome 验收；给出依赖、每个任务的输入/产出、负责人会话边界、验收和完成定义。保持与用户要求一致的有限并发和统一引擎锁。此任务不要创建这些实施会话。
