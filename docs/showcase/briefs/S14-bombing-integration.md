# S14 实际轰炸与截击接入

本卡承接用户的B-25、实际轰炸／战斗机拦截和禁止预设单位演出要求。由既有S14聊天执行、统筹验收；不另开聊天或启动子代理。继续采用已复核的港湾自主阶段，见 `../acceptance/S14-expansion-phase-review.md`。BOMB最终清单须由统筹明确准入后才可复制；本卡不准入其工作中目录。

## 交付行为

同一普通Showcase菜单中至少可直接进入B-25攻击实际日本舰艇、战斗机拦截实际轰炸机；按冻结BOMB能力同时接入SB2C／D4Y俯冲、G4M水平轰炸及另一组截击场景。B-25／G4M允许明确的在空初态，不虚构机场起降。已有静态检视与原战斗机编队、十段训练均保留。

场景只提供初始编制、位置、合法已知目标／区域和高层任务。进入投放、离架、漏失／命中、受损中止、脱离与返航均消费实际状态。选择能观察到接近过程的初始距离，不依靠延迟开火、无敌或强制命中制造镜头。程序指挥官与用户将来接入的命令继续走同一入口。

私有机制夹具中的被动泊舰／岸炮只证明指定机制。普通场景沿生产ShipMotion、己方探测、防空、弹药和DM运行；不把港口装饰物当作可摧毁单位。双方真实指令和执行状态须能从正常UI查看。

## 组合要求

- 沿 `../S14-BOMB-integration-inputs.md` 合并Session、World命令校验、性能角色与任务／OPS桥，不安装第二套AircraftSuite或运动积分器。
- 每个编队只有一个高层任务管理者。FleetPlanner与BombingCommander不得交替覆盖同一战斗机；可复用现有舰队策略或明确分配职责，不能用永久human来源锁住AI任务。
- 保留无防御枪但有炸弹的资源语义；投完后的拉起／脱离仍归当前任务。低油、空载、目标丢失和真实损伤继续改变行为。
- 新模型表现消费真实挂载、舱门／摆架／减速板、控制面和DM。现有SB2C战损不能因替换Adapter消失；当前BOMB视图的SB2C分支需组合旧DM能力。多发机独立发动机、防御枪位、日军与陆基作业未完成的能力分别记录。
- 只读镜头围绕当前任务阶段、实际弹体和真实事件观察；相机切换不改变单位、炸弹或战果。用户能自由观察并重新跟随。

## 验收与正式入口

先在私有组合中检查唯一模块与任务所有权、四型实际投放／完整离架、真实截击干扰、原枪炮／DM／OPS回归，再冻结运行清单。验证包含更远来袭、低油／空载／失去目标等条件变化，保留未击中或未截获结果。重复检查只用于有变化或尚未解决的风险。

2026-11-12 统筹澄清：四型离架能力沿用同版 BOMB 机制证据，普通对抗场景不要求四型在每个默认初态都成功投弹。SB2C 移动舰目标出现真实高度不足中止、返航后遭防空击毁，应保留原成功投放断言失败，并另核中止原因、库存不扣、实际拉起／返航／坠海；不能将它写成普通场景投弹通过。当前主要新增场景由已真实投放的 B-25／D4Y／G4M 和两组真实截击交付，不通过弱化防空、虚构战果或反复挑选必胜初态来统一结局。

Chrome通过普通菜单操作，实际查看编队、投放和弹着、拦截射击与受损／中止、双方任务状态；验证暂停／倍率／重开，不以脚本直接写模拟状态跳到结果。原生取证与Chrome各自记录来源，临时进程和服务须清理。

组合最终版补完尚未终验的双机两波次：根据已有1560秒进近进度给予合理的验证时长，减少重复档案开销，不改变完成条件或飞行状态。该项不以私有OPS夹具的旧通过替代。

统筹复核后，S14统一按逐路径清单和已有before备份准入公共文件、白名单及`expanded`普通入口。正常启动拟为 `python3 tools/run_first_playable.py web --scene expanded --build`，原`all`入口保留。随后交既有S08完成组合包的普通启动、Chrome长测与性能复验。当前阶段短Chrome不能作为长期或稳定30FPS结论。
