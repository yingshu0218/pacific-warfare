## 目标和边界

把战场与电影镜头作为画面主体，让用户一眼知道双方在做什么，按需追查某条命令或单位的行为。视觉保持简洁、现代、克制，适配当前简化的海面/岛屿/历史单位模型；不把观战界面做成密集管理后台，也不依赖复杂模糊、发光或高成本全屏特效。

第一版只观战。双方 AI 指挥摘要与真实执行过程必须保留，为 V2 人类指挥预留读写边界，但本次不设计假装已经可用的战术下令按钮。不得编造实时数据、进度百分比、指挥官台词或装饰性目标锁定。

只读 `AGENTS.md`、`docs/showcase/command-and-observer-ui.md`、`docs/ui/current-ui-audit.md`、`ui/observer_hud.gd`、`ui/observer_map.gd`、`scripts/game/first_playable.gd`、相机和指挥读模型。参考 S09 地图、S10 岸防任务、S11 音频规划；不改其他板块的文件。不创建下级聊天或子代理。

## 必交设计

1. **信息架构与三个观战状态。** 默认电影观战保留双方紧凑任务摘要与少量播放控件；战术查看展开命令/地图/编队；选中单位查看适用的详情。定义切换、返回、互斥面板与纯净 HUD 隐藏规则，不让状态越用越乱。
2. **三种视觉方向与待授权概念图。** 先用文字完整定义三种有意义的布局和取舍。仅在统筹核验用户明确授权后，才使用 Product Design 与 ImageGen 的相关技能，基于获准且已实际查看的当前截图生成三张独立图；每张单独调用生成，不拼成一张。区别来自信息组织和操作位置，不只是换色。保留当前游戏世界的简化模型、海面与镜头，不生成不切实际的 AAA 战场代替本项目。图为设计提案而非已实现截图。每张附一句适用性和取舍，给出推荐。
3. **推荐布局规格。** 以 1280×720 为最低验收尺寸，说明 1920×1080 扩展、中文字体与间距、主要面板尺寸/安全边距、最少点击路径；默认 UI 遮挡面积以约 15% 为候选目标，需后续实测，不为硬凑数隐藏必需信息。色彩用中性深色和克制的阵营色，状态不能只靠颜色表达。正文候选 14–16 像素起，中文需实机阅读验证。
4. **内容和状态规范。** 摘要须关联真实命令 ID，显示受令对象/任务/执行摘要，完整双方任务可一步展开。长名称、多个编队、空记录、目标失联、命令拒绝/替代/完成、单位失效、暂停、战斗结束、重开都要有合理状态。默认不要将每次射击刷成高层命令。飞机、舰船、岸炮/高炮各自显示有意义的字段；不同弹药分类展开。
5. **操作规则。** 暂停/倍率、自动电影/自由/跟随、命令定位/地图定位、声音/音量、战报、结束/重开的分组。尽量延续已有快捷键，避免焦点吞掉空格；战报独立模态且有清楚的关闭方式，保持焦点/观察目标的可恢复性。UI 不应改模拟结果；既有 Web stream 音频和幂等暂停修复必须保留。
6. **Godot 实施拆解。** 拆成主题/组件、读模型与状态层、默认 HUD、战术面板、单位面板、战报/设置、接入与验收，列输入/输出/依赖/验收。复用现有事件、命令与状态接口，UI 不扫描/操控 AI 内部状态。按变更驱动更新，避免增加每帧全量节点构建。仅规划，不运行实现。
7. **验证方案。** 使用真实战斗状态验证 720p/1080p、长中文、面板层级、鼠标/键盘操作、失效/重开、三类单位适配。Chrome only，遵守 tools/verify.py 共享锁、最多一个引擎、超时与清理。正式 UI 实现后再补 Chrome 性能对照，不把原生截图或概念图当成功能/性能验收。

## 推荐探索范围

- 外围轻 HUD：上沿双方两条简短任务，底部中央小型播放条，点击展开右侧战术抽屉。
- 底部战术栏：把双方摘要与播放集中到低矮底栏，顶部尽量留空；展开时为明确的战术工作区。
- 情境侧栏：固定一条细导航轨，指挥/单位/地图在同一侧栏切换，世界区域稳定；默认侧栏收起为摘要。

可以调整上述方向，但三张须在相同世界和数据语义下比较。默认推荐外围轻 HUD；最终视觉选择由用户看图决定，当前任务交付完整方案后停止，不自动实现。
