# S05 执行卡：探测、武器、碰撞、损伤与基础视听

本卡由统筹准备，在对应独立聊天创建后执行。范围为 T05–T11；不造舰、不编写飞机／舰队运动、不制作最终观战 UI。依赖 S01 运行契约，使用六型模型的正式定义。第一版画面简化，但所有可见战斗来自实际模拟。

## 先发布可消费的接口

先在 `docs/combat-contracts.md` 发布实际将实现的最小接口，并尽早告知统筹，让 S04／S06 可以同步接入。沿用 `SimulationModule`、统一命令、逐实例状态和事件；不要重写世界。

- 接触数据：实体 ID、最后观测位置／速度、观测时间、分类和有效状态。规定过期规则。敌方精确实时状态不得经辅助函数泄露给指挥和任务决策。
- 行为输入：单位目标、是否开火、飞机点射窗口等低层意图；S04／S06 不直接生成弹丸或扣库存。明确这些字段的单一写入者、读取时序和复位规则。
- 损伤输出：结构状态、动力／操纵能力、失效武器、起火／进水／坠落等供行为和表现读取的字段。损伤模块拥有其写入权。
- 事件：开火、命中、空爆、海面／地面撞击、受损与失效的真实位置、来源和必要尺寸。展示层去重与池化，事件消费频率不影响模拟结果。
- 新增数据放各自模块参数文件；确有必要扩展公共类型时，先向统筹说明字段和影响，由一个所有者修改并回归 S01 测试。不要把运行参数藏入历史来源说明中。

## 实施与验收

1. **探测与目标。** 基础目视／雷达范围和视线条件、己方情报、最后接触与失联；保留时间戳，按有限更新频率工作。没有接触不等于所有敌人都可被精准追踪。目标选择有威胁／距离等实际理由及换目标冷却。对海任务目标由行为给出，防空可在任务允许的职责内分配来袭目标。
2. **炮位与库存。** 使用实际安装点和逐管炮口，训练／俯仰速率、限位、装填周期和逐管库存。未就位／超射界／无弹／炮位失效不能发射。主炮齐射只含就绪炮位，主副炮职责清楚；舰体及上层建筑遮挡需要有与模型大形相符的简化约束，不能穿舰开火。
3. **火控。** 使用有时效的接触信息求移动目标提前量、弹道和散布；飞机固定武器由机体朝向及实际点射窗口约束。高炮使用合理的定时空爆，小口径保持直击；不让机枪变成重高炮炸云。不用“指定目标即命中”。
4. **弹丸和碰撞。** 固定 tick 推进，沿经过的路径检测最先碰撞；包含运动单位的相对运动，检查薄障碍、高速穿越、友方拦截、海面和地面。碰到 nearer 对象就结束该弹，不继续追指定目标。分清发射者初始自碰排除与其他友方碰撞，明确友伤规则。引信／撞击只结算一次。
5. **伤害。** 简化且可解释的结构／少量部位状态，动力、操舵、武器失效和必要持续伤情。大口径与机枪的有效对象不同，不能靠统一巨量 HP 或固定时间扣血伪装战斗。历史尺寸／初速／射速有来源，游戏毁伤近似明确标注；不为两阵营平衡改历史性能。失效和残骸有明确回收阶段，真实状态供任务退出和战报使用。
6. **表现。** 枪口火光、曳光／可读弹迹、海面水柱、地面尘土、命中火花、重高炮空爆、烟火和简洁声音，使用 Compatibility 可运行的少量模板与有上限的池。显示池满／关闭效果不能取消发射、碰撞或伤害。声音记录原创／来源；不得以用户提供外部音效为前置。

测试以可计算的受控场景为主：射击时序与库存守恒、真实炮口、限位／遮挡、移动交会、最先碰撞、水陆分类、引信只触发一次、损伤能力变化、不同显示消费与帧步结果一致。测试应证明机制，而非仅检查计数器增加或复述实现公式。

使用局部无 UI 的验证场景展示基础效果，可少量原生截图后退出；模型已完成模块和装配验证的组合才用来实拍。正式 Showcase、电影镜头、双边指挥 UI 与浏览器整体验证交 S07／S08，不能用测试桩代替最终集成。
