## 从真实接口得出的实施要点

1. 当前 HUD 每 0.25 秒刷新，命令签名改变时清空重建列表；新 UI 用 ID／changed_tick／sequence 增量更新，关闭页签不渲染，避免每帧复制世界或全量建节点。
2. `FirstPlayableSession.journal` 上限为 240，当前 UI 约显示最近 70 条；规划准确称“近期指令记录”、分页显示，不宣称完整战斗回放。命令拒绝可以只有 command ID，不能伪造 accepted order。
3. 当前选择命令会同时定位，相机选择器会立即跟随；规划将“查看”“定位”“跟随”分开。无效目标不能沿当前定位回退逻辑误转向受令部队。
4. 当前单位共用舰艇式字段，`definition_index` 只有 domain／炮位 role；需要真实静态定义索引与舰／机／ground 分支，弹药按武器定义／弹种统计，兼用炮不重复。
5. 当前 report 用 ship／else 分类；统筹已将 ground 的战报、任务读取与事件镜头分类兼容明确写入 S10 执行卡，本轮也已只读核对。S12 依赖该契约，不做运行代码修复；S10 未发布最终字段前，岸防分支保持待接入／待验收。
6. 当前工程逻辑尺寸为 1440×900 并使用 canvas_items 拉伸；720p／1080p 方案以最终可见尺寸计，实施时须核验变换与输入命中。1080p 抽屉最终规格为 x1416／y136／w480／h844／下沿980，与摘要下沿112和播放条上沿1004各留24。
7. Web STREAM 与幂等暂停保护已经存在。规划明确保留 Space 优先处理，新增 UI 焦点导航不能退回“点击声音按钮后 Space 再触发声音”的旧问题。
8. 性能口径保留当前 Showcase 1280×720 稳定30 FPS、p95≤33.3ms 的既定要求；60 FPS 与未来1440×900／满编制目标另述，UI CPU 与默认遮挡面积只是待测候选值。
