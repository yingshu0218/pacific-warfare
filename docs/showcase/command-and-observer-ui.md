# 战术指令与观战 UI

更新：2026-11-10。用户明确要求程序指挥官模拟真人下达大指令，正常 UI 可查看双方指挥任务及执行，后续接入真人沿用同一入口。本要求属于首个 Showcase 的正式交付。

## 责任边界

程序指挥官／未来真人 → 同一高层命令校验与分发 → 编队任务规划 → 单位执行 → 火控／运动。高层命令表达目标和意图，不逐帧旋转单位，不直接改变坐标或结算伤害。

首段命令覆盖：区域巡逻、护航／保护核心舰、拦截敌机、对海接敌／集中攻击、重新集结、脱离／撤退。具体受令编队必须具备相应能力；未接入的起降、航空攻击等命令明确拒绝，不能假装执行。

S01 提供契约和状态／事件基础；S06 实现指挥官决策、任务分发与生命周期；S04/S05 等执行模块通过同一接口回报结果；S07 实现观战界面。不能由单一聊天包办所有板块。

## 最小指令记录

- 稳定指令 ID、来源类型（程序／真人）、下令人及阵营。
- 接收对象：舰队、双机／四机编队或明确单位，不依赖 UI 节点引用。
- 指令类型、目标单位／区域／航点和任务意图。
- 下达时间、接收时间及最近状态变化时间（使用仿真时间）。
- 状态：已下达、已接收、执行中、完成、失败、取消、被新命令替代；无效命令另记拒绝理由。
- 真实执行进度或摘要，例如“正在转向展开”“僚机掩护”“目标失联后继续搜索”“低油脱离”；不得编造预设台词假装战术发生。
- 状态改变的原因、关联目标或替代命令 ID，便于 UI 和验收追踪。

最终字段名由 S01 契约统一。支持重复投递去重、目标失效、编队成员损失、命令替代／取消和重置清理。一次高层命令可产生多个执行动作，但不能把每次瞄准／射击都当作新的指挥官命令刷屏。

## 正常观战界面

默认在简洁画面中保留双方的紧凑指挥卡：阵营、当前主要任务、受令对象、执行状态。提供清楚的“指挥态势”展开入口，展示按时间排序的双方命令与执行变化；选中命令可定位相关编队或目标。

展开视图显示“谁向谁、何时、下达什么、执行到哪一步、为何结束或调整”。状态文字面向普通观众，不显示内部类名、原始 JSON、tick 编号或调试字段。细节可用仿真分秒及易懂名称。电影模式允许收起面板，重新打开仍能看到当前状态和近期历史。

双方命令展示属于观众视角，可看双方；程序指挥官只使用己方可得情报，不因 UI 全知而获得敌方实时位置或敌方指令。观众读模型与指挥官情报输入必须分开。

## 港湾实战中的两个岗位

日美各设舰队指挥官和航空指挥官。舰队岗位决定水面编队的接敌、护航、巡逻或脱离任务。航空岗位给双机／四机编队分配拦截、掩护和已有轰炸目标。双方各自按本方掌握的接触、可用兵力及损耗判断进攻、平衡或保守。姿态持续一段时间，避免接触短暂波动就反复换令。进入保守时可推迟新出动，已承诺的轰炸由机组继续执行，并可因伤情或失去目标而中止。

观众在「指挥态势」中可同时看四个岗位的当前姿态与理由。选择一条命令可以查看签发者、受令编队、目标、下达时间和执行回报。选择一艘舰时，详情列出各类炮组实际分配的目标和待命状态。炮组分配与真实开火分别记录，装填、失能或射界受阻时仍可区别看待。[双指挥官交付](../deliveries/CMD02.md) · [舰炮分配交付](../deliveries/GUN01.md)

## 验收

1. 真实自主战斗产生双方高层命令，能从命令 ID 追踪到受令编队的行为变化及终态；不能只列一张静态计划。
2. 无效／不具备能力的命令被拒绝，有可见原因；取消／替代后旧任务不再控制单位。
3. 受损、目标失联、目标摧毁、低油／无弹等导致实际状态变化，UI 能呈现其中适用的执行原因。
4. 改由测试的人类来源提交同类型命令，经过相同校验／分发，不需要重写单位行为；正式玩家指挥操作仍留 V2。
5. 暂停时仿真状态不变；慢放／倍速正确；重开清空上局指令和悬空目标引用。
6. 正常 UI 有双方当前指挥与展开时间线；真实原生及浏览器截图／操作证据能够验证。不得仅以控制台日志或调试 HUD 代替。
