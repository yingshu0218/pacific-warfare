## 显示测量与归因

以下是统筹同批次 Ego Lite 旧包记录，**不是本实施沙箱重跑**。数据为浏览器 `requestAnimationFrame` 调度间隔，不是 GPU 合成或屏幕扫描输出时间。诊断帧与运行帧分别取样，不能从各列分位数相减推出渲染成本。[旧包原始数据与验证编号](../showcase/evidence/PF01/coordinator-baseline.json)

| 旧包采样 | n | p50 / p95 / p99（ms） | 状态与实测尺寸 |
| --- | ---: | ---: | --- |
| 未注入游戏探针的常规页 | 42 | 1033.2 / 1041.8 / 1045.5 | 45.22 s；跟拍，采样帧可见且聚焦，CSS 画布及 WebGL 缓冲 1280×720；浏览器用 1280×720/DPR 1 指标覆盖；这组不读模拟时钟 |
| S08 探针，运行 | 22 | 1033.3 / 1041.8 / 1041.8 | 24.21 s；可见、聚焦、27 单位、1×；诊断仅把光栅缓冲调为 1440×900，Godot 视口仍是 1280×720 |
| S08 探针，同页暂停 | 75 | 33.3 / 41.7 / 1008.2 | 6.42 s，含刚暂停的长间隔；缓冲及可见、聚焦条件同上，采样状态保持 tick 272 |
| 同批统筹原生旧包 | 2736 | 16.543 / 32.201 / 62.848 | 1280×720、跟拍，预热 2.5 s，结束于模拟 53.0 s；非 Web，不当作浏览器过线 |

- **页面调度：** 上一轮同设备简单画布 24 个 rAF 间隔 P95 为 73.5 ms，说明该自动化条件本身也可能超预算，但不能用它解释港湾完整运行的约 1 秒间隔。旧包运行探针的内部步长 P95 为 141.9 ms（n=24），与页面调度 P95 1041.8 ms 并不相等。游戏探针首尾在 16.49 壁钟秒推进 128→256 tick，即 2.13 模拟秒（约 0.13× 的实际推进率，界面仍显示 1×）。不能把浏览器长间隔写成模拟在正常等速运行。[历史简单画布](2026-11-19-aerial-motion.md#ego-lite-实测)
- **模拟及观战快照：** 对应旧包浏览器 n=24，推进＋快照 P50/P95/P99 为 85.2 / 147.3 / 149.9 ms；表现为 2.9 / 3.8 / 3.8 ms、相机 0.3 / 0.4 / 0.4 ms、HUD 0 / 0.8 / 3.5 ms。相机和 HUD 并非此短段最强信号；无头分离测试另显示规则推进本身占主要 CPU，不能靠少算来解决。
- **3D：** 旧包探针采到运行约 1218–1245 draw calls、64.0–67.3 万 primitives；暂停状态仍约 1231 / 61.8 万。保留了绝大部分 3D 工作而调度明显恢复，说明不能把运行时整段停顿都归给 3D。暂停仍越过预算；没有同机同帧的只关闭 3D／只关闭 HUD 或 GPU present trace，不能定量分出渲染、组合器和线程等待。
- **本聊天环境：** 两次独立尝试的 localhost 随机端口 `bind` 都被沙箱拒绝；Ego CLI 初次启动也报无法启动，未创建窗页；本聊天的原生窗口尝试退出 `-6`，没有产生帧样本。所有验证经 `tools/verify.py` 同锁、串行、有超时，进程组清理成功；没有访问或关闭用户原有页面，没有残留 PF01 服务或窗口。候选实际显示、光栅/视口同为 1440×900、以及 33.3 ms 目标均待统筹复测。

## 单一修复与分离实测

`FirstPlayableGame` 每帧已得到一个独立的插值观战字典。`CombatEffects` 以前又对全体单位及其嵌套状态做一次深拷贝，实际只读。让普通路径直接借用该帧，重置时释放引用而不清空调用方字典；通用 `apply_snapshot` 仍保留防御性复制。事件接收、可视池、烟火位置、引擎声更新、炮弹/炸弹视图、相机和 HUD 原样保留。没有改变模拟/战果、事件节奏、渲染分辨率或任何观战开关。

冻结源无头执行真实港湾场景，手工调用原 `_process` 并使用现有分段计时点。预热 180 调用，固定 `1/60` 或循环 `1/120, 1/120, 1/30, 1/60` 秒，固定步长运行和混合步长运行均测 tick 180→3600、推进 57.0 模拟秒、最终无积压。暂停冻结于 tick 180，推进 0 秒；`World` 只运行同一规则世界并排空事件，不运行观战阶段。墙钟包含摘要开销；下表只列相应调用内 CPU，**不是实际显示帧**。[CPU 原始分位、状况与摘要](../showcase/evidence/PF01/cpu-and-verification.json)

| --- | ---: | ---: | ---: | ---: |
| 旧包源，暂停 | 600 | 2.38 | 2.20 / 3.19 / 3.82 | 1.59 / 2.33 / 2.96 |
| 旧包源，World | 3420 | 28.53 | 5.92 / 10.87 / 58.53 | — |

混合步长中，推进＋快照 P95 `16.01→15.73 ms`，表现 P95 `5.41→4.13 ms`（-24%），整体 P99 未改善。固定步长的推进＋快照 P95 也在独立进程之间波动（`15.95→8.48 ms`），因此不把该组的整体改善都归功于特效修复。旧包固定组 HUD P95 0.33 ms，HUD 段至少 20 µs 的 214 帧中 P95 8.70 ms，不等于持续 HUD 成本。保留显示能力，不靠降低画质试图过线。
