# 现代观战 UI 文字方案

日期：2026-11-10。任务：S12。状态：**文字规划与三张视觉提案完成，用户已选定第 1 张“外围轻 HUD”；运行界面未实施，功能与性能未验收。** 本方案固定 Godot `4.7.2.stable.official.ed1daf0bf`、typed GDScript、Compatibility，V1 仅观战。三种方向的比较见 [directions.md](concepts/directions.md)，本轮实际检查见 [S12 交付](../showcase/deliveries/S12.md)。

## 1. 设计结论与依据

**已确认方向（2026-11-10）：** 用户选择第 1 张 [外围轻 HUD](concepts/01-peripheral-hud.png)。后续 UI01–UI08 以该图的布局方向和本方案的交互/真实数据规范为准；像素尺寸按 Godot 实际适配验证。当前实施任务尚未启动。

推荐“外围轻 HUD”：上沿保留双方真实任务的紧凑摘要，底部中央保留播放与观察入口；指挥、地图和单位详情共用右侧抽屉。默认把战场留给电影镜头，查阅时只展开一个工作区。战报使用独立模态层。

本轮逐张打开并查看了 [默认观战](evidence/current/01-default.png)、[展开指令](evidence/current/02-orders.png)、[跟随飞机](evidence/current/03-fighter.png)、[查看战报](evidence/current/04-report.png)、[收起信息](evidence/current/05-cinema.png)。它们是 1280×720、仿真 2 秒时的真实原生截图，采集条件见 [capture.json](evidence/current/capture.json)。它们没有证明浏览器输入、1080p、可访问性或性能通过。

| 已观察到的问题 | 对应设计决定 | 后续验收依据 |
| --- | --- | --- |
| 默认两张大指挥卡合计约占画面 27%，每个编队同时常驻 | 每方默认只显示一条真实任务，加其余任务数量；全部任务一步展开 | 默认两方摘要都可读，原有有效命令全部可追查 |
| 指挥展开后双栏覆盖约 61%，空历史仍留大面板 | 单侧抽屉，当前任务与近期时间线分开；详情替换列表 | 720p 不同时叠两块指挥详情，没有用于填空的虚构记录 |
| 底部 13 个控件并列；收起信息后仍有 12 个 | 底部六组入口；结束、重开等低频操作移入菜单 | 常用控制不用展开长工具栏；纯净观战真正隐藏 HUD |
| 战报被上方指挥卡遮住 | 模态使用独立 CanvasLayer、遮罩和焦点范围 | 所有普通面板都不能挡住战报标题、内容或关闭按钮 |
| 飞机出现“进水”，弹药跨口径合计 | 按单位域与能力选择字段，弹药按武器家族／弹种展开 | 飞机无进水，固定阵地无航速／燃油，兼用炮不重复统计 |

[指挥与观战契约](../showcase/command-and-observer-ui.md)优先于装饰性取舍。默认显示双方真实任务；观众全知只用于观察，不进入程序指挥官情报。V2 的人类命令仍通过统一校验与分发入口，本次不放置不可用的下令按钮。

## 2. 信息架构

信息分三层，层与层之间有明确入口：

1. **持续看懂战场。** 双方任务摘要、仿真时间／暂停／结束状态、当前倍率、镜头模式和主体名称。自动切镜不自动打开单位面板。
2. **解释当前行为。** 一个右侧抽屉，三个页签为“指挥”“地图”“单位”；可以查看命令、成员、地点和所选单位。抽屉打开不暂停模拟。
3. **管理本次观看。** 战报、声音设置、帮助、结束、重开。战报／设置／确认框使用单一模态宿主；结束和重开有具体确认内容。

底部播放条只有六组：暂停／继续、倍率、镜头模式、态势、声音、更多。倍率沿用 0.5／1／2／4×。镜头模式菜单包含自动电影、自由观察，以及选择跟随单位入口。“态势”一步打开全部双方当前任务，页签进入地图或单位。更多菜单包含战报、声音设置、操作帮助、纯净观战、结束本场、重开本场。

默认不显示常驻小地图、完整单位统计和各炮位库存；它们在相应抽屉中有固定位置。声音仍有独立可见入口，首次点击明确启声。更复杂的混音选项遵循 [S11 音频规划](../audio/production-plan.md)，本次不把它们当作已经接入。

未来每方 20–30 舰／100 机时，默认仍是固定大小的两条摘要与同一播放条，不随单位数增高或扩成几百张卡片。指挥阅读以舰队／飞行编队／驻军为主，成员按需展开；单位查找在抽屉中按阵营、域、编队、状态分组／筛选，并支持名称搜索。只挂载当前页或可见组的条目。当前 Showcase 不实现或验收该规模，也不为此新增管理后台。

## 3. 三种观战状态与状态边界

### 3.1 基本状态

| 状态 | 常驻内容 | 右侧区域 | 进入方式 | 返回规则 |
| --- | --- | --- | --- | --- |
| 默认电影观战 | 双方摘要、播放条、时间、当前镜头简述 | 收起 | 首次装配成功、重开成功、关闭抽屉 | 不自动弹出详情，不因镜头跟随某单位切入单位状态 |
| 战术展开 | 双方摘要与播放条仍保留 | 指挥或地图；指挥含当前／时间线及单条详情 | 态势、世界焦点下 Tab、点击摘要、相关详情链接 | Esc 先从详情回列表，再关闭抽屉；顶部关闭按钮直接回默认 |
| 选中单位 | 双方摘要与播放条仍保留 | 单位详情或单位列表 | 单位列表、小地图标记、指令成员入口 | 返回到此前抽屉页签及列表位置；若从默认进入则回默认 |

相机模式 `auto / free / follow`、模拟播放 `running / paused / ended` 和上述界面状态彼此独立。开抽屉、过滤列表、查单位不切镜、不发战术指令。只有明确点击“定位”或“跟随”，或使用既有相机输入，才改变镜头。

只保留一层可恢复的来源上下文，避免“单位→命令→单位”无限堆栈。保存的是页签、筛选、所选 ID 和滚动位置；跨对象链接更新此上下文，不生成连续弹窗。抽屉详情中的“返回列表”和整体“关闭”分别表达一级返回与回到战场。

### 3.2 状态转移

| 输入／事件 | 结果 | 必须保留或清除 |
| --- | --- | --- |
| 默认点击某方摘要 | 打开该真实命令详情；无命令时打开该方当前列表的空状态 | 保留当前镜头、倍率和暂停状态；“全部任务”入口不施加阵营筛选 |
| 任意非模态状态点击“态势” | 打开指挥的双方当前列表；已在此列表则收起 | 不累加第二个抽屉，不重置另一页签的筛选 |
| 指挥详情点成员／地图点单位 | 用同一抽屉显示单位详情 | 保存原命令 ID／地图状态，镜头不动 |
| 单位详情点“当前指令” | 显示真实 `active_order_id` 对应的详情 | 保留单位返回入口；ID 不存在时说明当前无可查记录 |
| 点击“定位部队／目标／地点” | 相机进入自由观察，定位当前可用位置 | 抽屉仍打开，不隐式跟随；在播放条明确显示自由观察 |
| 点击“跟随此单位” | 相机进入跟随，抽屉保持当前状态 | 选择 ID 与跟随 ID 分开保存 |
| 自动电影切镜 | 只更新镜头简述 | 不替换已选单位、不抢走列表焦点、不改命令筛选 |
| 重复打开同一对象 | 更新其内容，不重复创建节点／返回层 | ID 以 `(generation, id)` 识别 |
| 单位退场／命令终止 | 当前详情保留真实终态，可返回列表 | 不自动跳到同阵营另一个对象，不继续用旧引用跟随 |

### 3.3 纯净观战

H 或“更多→纯净观战”是主动开启的 HUD 隐藏覆盖状态，区别于默认电影观战。隐藏摘要、时间、播放条、抽屉、地图、单位标注和镜头简述；进入时只短暂提示“按 H 或 Esc 恢复界面”，候选 2 秒后消失。指针移动到底边可临时露出“恢复界面”按钮，离开后收起，键盘恢复始终可用。

进入前保存基本状态、所选 ID 和列表位置，关闭普通弹出菜单；恢复后读取最新真实状态。H 不关闭模态，模态期间忽略 H。纯净状态仍可用 Space 暂停／继续、C／F 切模式；操作时可短暂显示结果后消失。自然战斗结束或加载失败必须退出隐藏，显示结束战报或错误。不能用纯净观战替代默认双方摘要验收。

## 4. 推荐布局规格

### 4.1 尺寸与坐标约定

以下均为**最终可见布局像素的候选值**：Chrome 页面缩放 100%，以游戏 canvas 内容区而非浏览器外窗计量。DPR、canvas CSS 尺寸、drawing buffer、Godot 逻辑视口需分别记录。当前根工程是 `1440×900` 加 `canvas_items` 拉伸；现有 720p 测试显式改变了尺寸，不能据此认定所有拉伸下都已适配。

实施时由 Showcase 入口与 HUD 布局层明确完成逻辑坐标到可见尺寸的换算，验证字号和点击命中。只把 1440×900 整体缩小到 720p 会使中文和按钮过小；只把 720p UI 放大到 1080p 会浪费空间。布局值应按可用宽高与字体档位计算，不全局修改根模型查看器的窗口设置。1440×900 的项目性能基准保留。

| 项目 | 1280×720 最低验收 | 1920×1080 扩展 | 约束 |
| --- | --- | --- | --- |
| 外缘安全边距 | 16 | 24 | 不贴浏览器边缘；有效高度不足时优先让抽屉正文滚动 |
| 双方摘要 | 每方 360×80，左上 `(16,16)`／右上 `(904,16)` | 每方 400×88，左上 `(24,24)`／右上 `(1496,24)` | 两行正文，内容间距 4；长名称省略，完整内容可键盘／点击查看 |
| 中央场次状态 | 最大 240×28，顶部居中 | 最大 280×32，顶部居中 | 仿真分秒、观战／暂停／结束；长场景名放更多菜单 |
| 播放条 | 最大 560×48，底中，底边距 16 | 最大 600×52，底中，底边距 24 | 六组入口；内部横距 8，控件最小可点高度 40／44 |
| 镜头简述 | 最大 320×28，左下，播放条上方至少 8 | 最大 360×32，相同位置关系 | 一行，仅实际主体与镜头模式；过长可省略，不滚动跑马 |
| 共享右抽屉 | 432×528，左上 `(832,112)`，下沿 640 | 480×844，左上 `(1416,136)`，下沿 980 | 与摘要、播放条各留至少 16／24；正文独立滚动 |
| 抽屉内边距 | 16 | 20 | 单列详情，禁止抽屉内再并列双阵营长详情 |
| 地图可绘区域候选 | 400×272 | 440×336 | 下方接地点／单位列表；地图同源投影，不拉扁岸线 |
| 战报模态 | 最大 880×560，居中 | 最大 960×720，居中 | 单一正文滚动，标题与关闭／返回区固定；始终在 HUD 上方 |

宽度 1280 至 1920 像素之间插值安全边距与抽屉宽度；高度由“摘要下沿＋间隙”至“播放条上沿－间隙”决定。16:10 的 1440×900 采用同一锚点规则。窗口临时低于 720p 时保持恢复／关闭入口、允许正文滚动，不宣称首版完整适配手机或竖屏。

默认不打开抽屉和地图，主体中心区域不放固定控件。以 720p 两个摘要、中央状态、播放条、镜头简述的最大外框合计估算为 `100160 / 921600 ≈ 10.9%`；1080p 对应约 `5.9%`。这是未实现的几何估算，忽略临时提示但计入面板内留白。**约 15% 为后续默认 HUD 实测候选目标**，不是已测结果。实测按可见绘制组件外框的并集计量，包含阴影／底板；不把全屏透明输入根节点算作遮挡，也不靠降低透明度或藏掉双方任务凑数。抽屉、模态、帮助不套用默认面积指标，须单独报告。

| 目的 | 从默认开始的路径 | 点击数候选 |
| --- | --- | ---: |
| 看双方全部当前命令 | 态势 | 1 |

## 5. 真实指挥内容规范

### 5.1 摘要与当前任务

每方摘要绑定一个稳定 `order_id`，两行包含“阵营、受令对象、任务／目标”和“执行状态、真实执行原因、其余任务数量”。ID 保存在组件数据中，详情可查看完整编号；默认不挤入内部代码、tick 或 JSON。

代表命令按**仅用于展示的固定顺序**选择：当前非终态的撤退、接敌、拦截、重组、护航、巡逻；同类取最近下达者，再以完整 ID 排序。代表项在任务集合或终态变化时重选，不能因每次执行进度更新而轮播。它代表一条可追踪的任务，不把它包装成整个阵营统一意图；“另 N 项”按其余真实非终态命令计数，N 为 0 时省略。下钻列表始终能查看其他任务。

受令对象按 `recipient_ids` 及编队成员关系解析名称，不能只显示 UI 当前跟随单位。执行摘要合并相同的逐成员状态／原因，若存在差异显示“部分成员……”，详情列出真实人数与成员。“2／2 已接令”可由记录计数得出；不得由航程或观看时长编造完成百分比。示例文字仅为字段组合规则，运行时必须来自当前记录。

指挥页默认显示双方当前任务，阵营分组顺序固定，不因数量变化左右换位。每行两行文本与状态，点击详情替换列表；不把每条命令包成多层卡片。筛选可用“双方／日方／美方”，默认双方；空列表说明原因，并保留另一方数据。完整的生命周期和成员执行记录由同一命令 ID 关联。

### 5.2 生命周期与异常

| 真实情况 | 面向观众的呈现 | 交互与数据规则 |
| --- | --- | --- |
| `issued / received / executing` | 已下达／已接收／执行中，附实际执行摘要 | 分别使用下达、接收、变化时间，不以 UI 打开时间充当任务时间 |
| 完成 | 已完成，附实际完成原因与仿真时刻 | 从当前列表退出，详情与近期时间线仍可查 |
| 失败 | 失败，附原因，例如“搜索后未能重新接触” | 不改写成目标被击沉，不自动重试指令 |
| 取消 | 已取消，显示真实来源／原因 | V1 无取消按钮；测试人类来源也使用同一日志 |
| 替代／部分改派 | 已被替代／部分成员另受新令，通过真实 `replacement_order_id` 链接替代命令 | 保留旧任务和未改派成员状态；不能整条错误标为完成 |
| 拒绝 | 请求被拒绝＋可读理由 | 拒绝通常关联 `command_id` 与请求，可能没有有效 `order_id`；不能伪造已接收任务 |
| 目标失联 | 指令侧显示“按最后接触搜索”等实际原因 | 观众可以另外看目标真位置，但标明“部队接触已失联”；不能用观众真位置修改命令摘要 |
| 目标失效 | 显示执行器实际回报；观众真状态单独注明 | AI 尚未知失效时，不替 AI 把搜索任务改为胜利 |
| 无法撤离／路径受阻 | 执行中 · 撤离受阻／航行受阻及真实原因 | `propulsion_unavailable / fuel_exhausted / coast_unreachable` 不能继续写“正在驶离”或伪造失败终态 |
| 个别成员损失 | 成员列表标退出／失能，保留其他成员执行 | 按 execution 与 assigned IDs 显示部分结果 |
| 未知枚举／字段未提供 | 状态待解释／未提供 | 正常 UI 不露原始原因码，也不替换成看似肯定的“正常” |

当前支持的高层任务为巡逻、护航、拦截、接敌、重组、撤退。起降、轰炸、鱼雷攻击等未接入任务不进入菜单和默认任务清单；如果测试产生拒绝，显示实际拒绝原因。岸防高层任务由 S10 契约决定，不在本计划里假定新命令已经存在。

### 5.3 时间线

时间线显示 `order_issued / order_status_changed / order_assignments_changed / order_execution_changed` 和高层命令拒绝，按仿真 `time_s` 与 `sequence` 排序，默认最新在上。同一命令详情内生命周期按时间从旧到新展开，避免用新旧方向相反的时间线混淆阅读。

`FirstPlayableSession.journal` 当前最多保存 **240 条近期指令记录**，执行状态／原因相同的重复记录会被过滤；现有 HUD 只绘最近约 70 条。新 UI 应展示可分页的近期指令记录，候选每页 40 条，标明“近期指令记录 · 最多 240 条”和最早可查时刻。不能宣称完整全局历史或倒带。`BattleOrder.history` 可补充该命令已有的生命周期；被截断的逐成员变化不能重建成假日志。旧记录不可查时保留当前真实命令并说明缺口。

行内显示仿真分秒、阵营、受令对象、任务、状态变化／原因；点行查看记录对应的命令与成员，能明确区分“当时发生了什么”和“现在执行到哪”。开火、瞄准、每发命中不进入高层命令时间线；战报统计另走真实战斗事件。若将来需要整场事件归档，应单独安排存储任务，不能悄悄增大无界数组。

用户向上翻阅时，新记录以“有新变化”入口提示，不强制滚回顶端。恢复最新时才滚到顶部。取消筛选后不丢当前对象，重开后所有旧页码／未读数／游标清空。

### 5.4 定位语义

“定位部队”使用当前受令成员的可用位置；全员已退场时只定位最后相关位置并注明，不转成跟随。“定位目标”明确定位目标或目标区域；目标 ID 不存在且无已知区域时禁用，并写明“没有可定位的位置”，不能误回退到受令部队。

详情区在失联状态下区分“定位部队最后接触点”与“查看目标真实位置（观众）”。后者只在观众读模型确有目标实体时出现，不把它回写为己方接触。地图目标区、最后已知点与真实实体使用不同标签／轮廓，避免只有颜色不同。选择命令本身不自动定位，修正现有“点记录即切镜”的干扰。

## 6. 单位与弹药内容规范

### 6.1 通用字段

单位详情的第一屏按“身份与状态→当前任务与原因→主要运动／损伤→武器弹药”排列。身份包括实际单位名、阵营、型号、配置日期和服役年；年代来自 `UnitDefinition`，不是观战场次日期。任务链接指向 `active_order_id`，没有任务时写“当前无高层任务”，不制造默认巡逻。

正文最多先显示 4–6 个关键值，其余在同一面板的分组中展开。0 是真实值；字段缺失不填 0，显示“未提供”或不适用时省略。不能由 `active=true` 独自推断所有系统正常。状态优先读取损伤阶段、退出标记与适用域契约。

| 单位域 | 首屏有意义的值 | 可展开内容 | 不应出现 |
| --- | --- | --- | --- |
| 舰艇 `ship` | 实际航速（节）、当前任务／原因、结构／火情／进水、动力或操舵受限（若有真实值） | 领舰／编队站位、主副炮及专用防空炮组、逐炮位状态、实际提供的燃油比例 | 伪造飞机余油千克、机动特技、没有数据来源的续航倒计时 |
| 飞机 `aircraft` | 速度（候选千米／时）、海拔与离地高度（区分）、余油千克、任务阶段／机动／安全状态、结构／火情 | 编队角色、目标／接触状态、机枪／机炮、已接入的挂载与航空作业 | 进水、舰艇操舵、未接入的起降状态、把视觉螺旋桨相位当真实转速 |
| 固定岸炮／高炮 `ground`（S10 发布后） | 阵地／位置名、型号、工作／武器失效／摧毁、真实任务／目标、可用炮位及弹药 | 逐炮位转向／俯仰／装填、地形或射界受限原因、结构／火情（契约支持才有） | 航速、燃油、进水、沉没、坠机、地面移动／重新部署按钮 |

速度内部仍是 m/s，UI 单位固定显示且按域换算；不混用“航速”描述固定阵地。海拔来自统一坐标基准，离地高度优先采用航空已发布值，不能把 `position_m.y` 直接标成离地高度。没有容量来源时只显示余油千克，不显示虚假油量百分比。航母／机场作业待行为接入后按能力追加，不预先放空的功能页。

当前 `FirstPlayableSession.definition_index` 仅缓存 domain 与炮位 role；新读模型需要从 catalog 一次性补齐名称／年代／日期／武器与弹药关联。`UnitState` 提供任务、实际运动和模块数据，UI 不能从模型节点姿态猜测模拟状态。

### 6.2 弹药与武器

按“宿主炮位角色＋武器定义＋弹药 ID”归组：主炮、副炮（注明兼防空）、专用防空、机枪／机炮、后续真实接入的炸弹／鱼雷。兼用炮只属于一个库存组，承担两个职责不复制库存。

每组显示可读武器／弹药名称、剩余数量与单位；展开显示各炮位 enabled、每管剩余弹与真实 `cycle_remaining_s`。不同口径／弹种不能合成首屏的“总弹药 106988 发”。如保留战报原有总消耗，它必须标为“所有弹药发数合计”，旁边可按类别查阅，不能据其比较双方火力。

当前 `WeaponState.remaining_rounds` 是逐管库存，`WeaponDefinition.ammo_id` 才能关联弹种；没有已装填弹匣／待装弹数据，不能画虚构的弹匣进度。装填秒数可以来自实际周期；阶段“瞄准／射界受限／武器失效”必须用战斗读模型已有原因，不能从 UI 定时器推测。缺少友好弹药名或炮位状态时，列为读模型补全项，不能按炮管数量估计库存。

### 6.3 失效、无对象和长名称

单位退场时保留最后可读状态与真实退出原因，停止跟随并保留最后安全镜头；“查看最后位置”与“返回自动电影”是观察操作。残骸存在不等于可战，也不等于应该从清单消失。切换存活／已退出筛选后才能从当前列表隐藏，历史详情仍可查。

单位列表按阵营、舰／机／岸防分组，组内稳定排序。无 ground 单位时写“本场未部署岸防单位”；空阵地可在地图地点表出现，但不计参战单位。无目标、无当前指令、没有武器分别有明确文本，不保留上一对象的字段。

名称较长时摘要／列表两行内省略，状态与对象类型不得被挤出画面；详情标题允许两行，完整名称在详情或可键盘触达的说明中可读。鼠标悬停提示不能是唯一获得完整名称的方法。数字按本地分组可读显示，单位不因位数变化跳位；极大数字用详细栏容纳，不用含糊的 K/M 取代真实库存。

### 7.2 组件职责

| 组件 | 内容与边界 | 交互反馈 |
| --- | --- | --- |
| 双方任务摘要 | 两行真实任务＋另 N 项；绑定 generation 与 order ID | 悬停／焦点可见；整条激活；未收到任务有空状态 |

| 字段行 | 名称、值、单位、可选受限原因 | 不适用省略；未提供与真实 0 分开 |
| 弹药组 | 武器／弹种归组与逐炮位折叠 | 展开只改变阅读状态，不停火、不转炮 |

## 8. 鼠标、键盘、焦点与模态

### 8.1 输入规则

| 输入 | 既有行为 | 规划行为 |
| --- | --- | --- |
| Space | 暂停／继续，已有优先处理修复 | 普通 HUD／按钮聚焦时仍只触发一次暂停，消费该事件；不能顺带开关声音或激活按钮 |
| C／F | 自动电影／自由观察 | 保留；模态或文本输入中不发送相机操作 |
| Tab | 切换指挥展开 | 世界焦点下打开双方当前任务并进入 UI 焦点；进入 UI 后 Tab／Shift+Tab 顺序导航，Esc 返回世界后可再用 Tab 打开 |
| H | 收起信息，底栏仍在 | 真正进入／退出纯净观战；模态中不生效 |
| R | 立即重开 | 打开“重开本场”确认，按键重复不重复创建；确认后才调用 restart |
| Esc | 无统一返回层级 | 先关闭普通菜单，再退出详情、抽屉或纯净状态；有模态时仅取消／关闭该模态 |
| 右键拖动／滚轮 | 旋转／缩放，自动模式下人工接管 | 保留，限世界区域；UI 内滚动不能同时移动相机，释放按钮必须结束拖动 |
| Shift+WASD、Q／E | 自由移动／升降 | 保留，文本输入、模态和 UI 导航期间禁止穿透 |
| Enter | 控件默认行为 | 激活当前聚焦控件；确认框初始聚焦取消，危险确认须主动选中 |

所有快捷键忽略 echo；同一事件仅由一个输入路由消费。文本筛选框中的字母与空格用于输入，Esc 先退出输入，不能边打单位名边切镜或暂停。菜单／抽屉支持键盘进入，不能只把所有 Button 设为 FOCUS_NONE 解决 Space 问题。模态内 Space 不控制模拟，也不作为结束／重开的快捷确认。

普通鼠标按钮点击后，播放快捷键仍可用；键盘焦点模式显示焦点框并按可见顺序导航。右键／滚轮在抽屉上由 GUI 消费。模态打开时取消相机正在进行的拖动，关闭后不能延续之前的鼠标锁定状态。

### 8.2 模态与返回

绘制与输入层级候选：世界 → HUD（20）→ 普通弹出菜单（30）→ 模态遮罩／内容（60）→ 必要操作结果提示（70）。CanvasLayer 数值由集成统一管理；普通指挥面板和地图不允许挂在模态层之上。一个全屏遮罩捕获输入，只有模态内容可点，点遮罩不穿透也不直接结束观看。

战报、声音设置、结束确认、重开确认共用一个 modal_kind，互相替换而不叠开。替换模态保留同一暂停所有权与返回上下文。错误模态无有效 session 时，不显示可用的播放／重开假按钮；给出具体资源失败摘要、关闭说明或可用的重试路径。

打开手动战报／设置／确认时自动暂停，记住打开前是否已暂停、倍率、generation、界面上下文和相机观察目标。仅首次进入模态申请暂停；关闭时只有“本模态暂停了仍在进行的同一场次”才恢复。用户原先已暂停、战斗已结束、重开已发生或加载失败时都不能恢复旧场。暂停属性仍只在变化时设置，不能为 UI 动画每帧重写。

模态标题与底部“返回观战／取消／确认”始终可见，正文滚动；Esc 和清楚的关闭按钮可退出战报／设置／确认。焦点限制在模态内，关闭回到原入口；原入口失效时回到态势或播放条。相机模式与跟随目标尽量恢复，但目标已不可跟随时保留最后安全视角并说明，不能复活旧引用或恢复过期世界坐标。

战报先申请暂停，再从同一 generation／tick 采集双方统计，标题标“截至 mm:ss · 已暂停”；不把不同刷新时刻的数字拼成一份战报。它是打开时快照，模态内不随定时器刷新；重开后重新采集，不复用旧场快照。结束战报使用终态快照，展示真实结束原因、双方可战／退出／损失，以及按域区分的统计，必要时展开各弹药类别。

当前 report 对非 ship 统一计作 aircraft。[S10 执行卡](../showcase/briefs/S10-shore-defence.md)已明确由 S10 所有者处理 ground 的战报、任务读取与事件镜头域兼容，S12 只依赖该输出，不扩成运行代码修复。UI 不靠单位名称猜域，也不将岸炮损毁计为沉没／坠机。

### 8.3 播放、声音与结束

暂停时清楚显示“已暂停”和倍率；倍率改变不隐式恢复。抽屉和选择不暂停，模态暂停明确可见。手动结束经确认后只调用现有 `session.finish()`，显示“观众结束观战”；自然结束显示真实结束原因。“继续查看战场”只关闭结束战报，世界保持结束，播放条显示“本场已结束”，恢复播放不可用。

声音默认关闭；播放条按钮为“启用声音／声音开／静音”，具体文案随真实状态，不自动开启或提升系统音量。首次启声从明确用户手势进入既有 Web 路径；主音量先提供一个总音量滑杆与静音，不依赖尚未接入的分总线。若当前运行仅有开关，总音量要列为实施接入项，不能做无效滑杆。音量调至零与关闭声音的生命周期应遵循 S11，不补播静音期间事件。

必须保留 Web `PLAYBACK_TYPE_STREAM` 与幂等 `stream_paused` 修复；Space 在声音按钮刚点击后仍只暂停。UI 不改音频后端、导出线程或引擎版本。战报／设置暂停、恢复、结束、重开要通过相同播放入口；声音源池与队列生命周期由音频模块负责，不由 UI 重建播放器。

## 9. 空状态、重开与场次恢复

| 情况 | 显示与操作 |
| --- | --- |
| 首次装配中 | 紧凑“正在装配战场”，不可操作的播放入口禁用；不预填双方任务 |
| 首 tick 前无命令 | 双方各“等待指挥命令”；时间线“尚无指令变化”；无大块占位卡和假日志 |
| 有当前任务但没有近期变化 | 当前列表正常；时间线说明“尚无近期状态变化”，不是“没有任务” |
| 当前任务全部结束 | “当前无执行中任务”，可查看近期记录和终态；不自动生成“已获胜” |
| 筛选后为空 | “此筛选下没有记录”＋清除筛选；区分数据未就绪和真实空 |
| 记录被近期窗口移除 | 说明仅保留近期记录；可查当前命令或已有生命周期，不能点到错误对象 |
| 暂停／模态期间对象失效 | 以打开时快照为准；返回后重新校验 ID，再展示最新状态 |
| 重开失败 | 保留仍有效的旧场状态并显示失败；若世界已不可用，进入加载错误状态，不假装已重置 |

确认重开后单次调用现有 restart，进入短暂装配状态，禁止重复确认；成功以新 generation 原子替换 UI 数据。清除旧命令／时间线／未读数／分页／筛选、选中单位／命令、悬停提示、模态暂停令牌、返回上下文和相机跟随引用。回到默认电影观战、1×、未暂停；实际世界初态以现有 reset 契约为准，控件从新快照同步，不能先把标签改成成功。

同一页面内保留用户已主动选择的声音开关、总音量、界面动效／文字设置；不重新播放“首次启声”，不补播上一局声音。若声音恢复失败应显示真实状态。重开不加载新场景实例来叠加世界、模型、地图和 HUD，也不变更种子／历史装备参数来制造更长战斗。重新加载页面的默认声音仍关闭。

### 12.3 性能、长时与清理

对同一最新 Web 构建、相同种子与镜头路径，记录 UI 隐藏、默认 HUD、战术／单位抽屉三种条件的稳定交战窗口（候选每种 60 秒，剔除热身）。记录 rAF p50／p95／p99、超过 33.3 ms 比例、模拟积欠、UI 刷新耗时／次数、可见行和 Control 节点数、JS heap、WASM 容量、页面进程内存；不能只看一个瞬时 FPS 或 WASM 固定值。

当前 Showcase 的既定验收口径是 **1280×720、稳定 30 FPS、p95 帧时间 ≤33.3 ms**，UI 改版沿用此门槛，不把它改称可随意调整的候选值。1080p 另记录新增像素成本与布局表现，不通过减少模拟单位／炮弹或关闭未观看交战换取通过。

60 FPS 是优化目标；未来内部 1440×900、每方 20–30 舰／100 机的完整规模另行验收，当前 Showcase 不能代替。UI 自身刷新 CPU 的默认 p95 ≤0.5 ms、展开 ≤1 ms（4 舰 8 机场景）仍是待测候选预算，需报告口径与帧间摊销，不与总体验收门槛混淆。

最终 S08 同版本至少累计 10 分钟实际可见有效战斗墙钟并三次重开，覆盖抽屉多次进出、时间线增量、声音开启时暂停与战报返回。可与 S11 同版本的有声长测合并采集；暂停和隐藏标签等待不算有效战斗时间，场景自然结束按原规则重开累计，不修改战果延长。检查 UI 行数／缓存／信号连接／模态节点不随运行或重开持续增长。

每轮使用明确 owner、进程／标签／服务归属、超时与 finally 清理，最多一个引擎；Chrome 功能操作与 HTTP 服务采用同一验证会话管理，保留锁至其结束。成功、失败、超时都关闭本轮临时原生窗口、Chrome 标签、预览进程和 HTTP 服务；不关闭用户原有窗口／进程，不使用 killall，不删除共享锁 inode。必要时独立检查所属进程组已消失；cleanup 不成功则该轮不能通过。
