# 现代观战 UI 的三个文字方向

日期：2026-11-10。S12 文字规划已通过复核，三张概念图由统筹在用户明确授权后完成；用户已于 2026-11-10 选定第 1 张“外围轻 HUD”。**下列是布局与交互提案，运行 UI 尚未实现。** 仅 `01-default.png` 与 `05-cinema.png` 两张获准截图用于 ImageGen；没有发送代码文件或其他项目截图。

详细状态、数值与实施任务以 [observer-ui-plan.md](../observer-ui-plan.md) 为准。本文件用于比较信息组织，不用三套配色冒充三种设计方向。

## 比较条件

三种方向都以本轮亲自查看的五张 [当前实际界面证据](../current-ui-audit.md)为依据：同样的简化舰机、海面、岛屿与镜头；默认必须有双方真实任务摘要，并可一步打开双方任务。任务绑定真实 ID、受令对象、执行状态与时间线，V1 仅观战。查看、定位、跟随分别表达不同动作。结束／重开不常驻一排大按钮，战报独立模态。

统一候选视觉语言为中性深色、中文 14–16 px 起、克制的日方暖色／美方浅蓝、文字状态＋形状提示、4／8／16／24 间距。无全屏模糊、装饰雷达或假进度；不把战场换成不属于项目的 AAA 海战，也不擅自把模型细节提高到新的制作标准。

最低比较尺寸为 1280×720，扩展到 1920×1080；所有面积均为未实现的候选估算，必须在实际 Chrome 中再测。三种方向都能使用相同的只读投影／状态层，选定方向后只实现一套外壳。

未来每方 20–30 舰／100 机仍保持固定默认占地，以编队级任务摘要为主，单位通过分组／筛选／名称搜索查找，不扩成常驻卡片墙；当前 Showcase 不实施该规模。战报统一为打开时暂停后、同一仿真 tick 的快照，关闭时只恢复本模态申请的暂停，不能混合不同时间的统计。

## 外围轻 HUD（推荐）

**方向句：把双方正在做什么留在画面上沿，把解释行为的细节藏在一个可返回的抽屉里。**

默认上沿左右各一条两行任务摘要，绑定各方一条真实高层任务，并显示其余当前任务数。时间／暂停状态居中，底部中央为低矮播放条。当前镜头主体只用一行轻提示。默认不显示大地图或完整单位详情，自动跟随某架飞机也不自动弹详情。

720p 候选：安全边距 16，两条摘要各 360×80，底部播放条最大 560×48；计入时间与镜头提示后的默认外框面积估算约 10.9%，后续以约 15% 为实测候选目标。1080p 增加边距和局部宽度，不把整套 UI 放大 1.5 倍。

点击“态势”一步打开右侧双方当前任务；点击摘要可直接查该任务。抽屉内切换指挥、地图、单位，同一位置一次只显示一个工作区；指挥详情替换列表，返回恢复原滚动位置。点击记录不动镜头，定位与跟随才接管相机。战报使用独立模态。H 主动进入完全隐藏的纯净观战。

最适合自动电影、全景炮战和机群特写。用户边看画面边知道双方的任务，信息位置稳定；从当前混乱 UI 迁移时可直接保留现有任务与观察动作。

取舍是需要在顶部、底部之间转移视线；720p 摘要不能同时列完八项任务，必须明确显示“另 N 项”，用一步入口查全。抽屉会覆盖右侧部分世界，需通过真实构图检查，不能把“透明”当成没有遮挡。

用户已选定这一方向。实现规格见主方案第 4 节。

## 底部战术栏

**方向句：把任务、时间和播放集中到画面下沿，让天空与远景尽量完整。**

默认使用一条低矮底部带：日方真实摘要在左，美方摘要在右，播放／倍率／镜头／态势位于中段。顶部只保留必要的暂停或场次状态，默认不散布角落卡片。任务与控制在一个视线区域完成阅读。

720p 候选：外缘 16，底栏可用宽 1248，高约 96，内部分为“日方摘要／播放／美方摘要”，任务用两行文字。底栏矩形约占 13.0%，另有必要状态时接近 15% 候选目标；长名称不能继续横向堆按钮，应将低频项放入更多菜单。1080p 底栏高度约 96–104，控制区居中，任务文字仍限合理行宽。

进入战术时底部带向上展开为明确的工作区，720p 候选高度 272–304：指挥、地图、单位页签共用一块内容区。双方当前任务用一列分组列表，详情替换列表；地图与详情不同时左右铺满。收起回到低底栏。跟随某单位时，底部任务区切到该单位详情须由用户主动选择，不能被自动镜头覆盖。

最适合经常暂停、读任务后再继续观看的用户。入口集中、左右阵营关系直接；上方完整天空对空战镜头有利。

取舍是底部战术展开会吃掉约四成高度，舰体、水花和低空机动容易与底栏相遇。720p 横向三段对长中文较紧，播放区宽度与双方摘要会竞争；跟随单位、长弹药列表和高层时间线都需要纵向滚动。默认底栏若始终通宽，会更像播放控制台，电影沉浸稍弱。

适合作为偏“分析观看”的备选。若用户强调看空战天空而经常暂停查阅，可以优先评估；无需为它另建一套数据接口。

## 情境侧栏

**方向句：用一个固定侧边入口管理指挥、地图和单位，使详细信息始终在同一位置。**

默认右侧保留一条细导航轨，提供指挥、地图、单位、更多入口；两方真实摘要在上沿相邻或分居两侧，底部只保留最小播放控件。不能为了收窄侧轨把双方任务隐藏成两个小圆点；摘要仍要能读到受令对象与实际状态。

720p 候选：安全边距 16，侧轨宽约 56，从摘要以下延伸到播放条以上；默认两条摘要各约 336×80，播放条约 360×48。计入侧轨与状态后的外框面积可能约 12%–15%，需实际测量。展开后由侧轨衔接一块 384–416 宽的情境面板，世界可观察区域长期保持相同的边界。

点击侧轨切换同一面板的指挥／地图／单位；单位选择直接替换面板内容，标题始终保留关闭与一级返回。用户可收起为细轨。若采用预留世界区域而非覆盖，镜头投影与点击坐标需随可用区域正确换算；这比覆盖抽屉的迁移成本更高，应在选定该方向后单独确认实现方式。

最适合长时间跟随一艘舰、频繁查单位和岸防状态的用户。所有详情有固定位置，导航易发现；后续 V2 人类指挥可能更容易容纳工具，但 V1 不能提前铺满下令控件。

取舍是细轨一直占边缘注意力；正文展开后更像分析工具，1280p 的世界横向空间较小。完全预留侧栏可能让电影镜头需要额外构图适配；若只是覆盖，则仍要解决主体被挡问题。三类实体的长详情容易让用户忘记已经选择了哪个对象，需要明确的标题与返回上下文。

适合作为偏“持续检查”的备选。不能以未来 V2 的潜力作为 V1 默认堆功能的理由。

## 取舍与推荐

| 比较项 | 外围轻 HUD | 底部战术栏 | 情境侧栏 |
| --- | --- | --- | --- |
| 默认电影画面的连续性 | 最强；中心世界保留充分 | 上方开阔，下沿持续占用 | 侧缘持续占用，世界横向更窄 |
| 双方真实任务的可见性 | 上沿同时可读，一步查全 | 下沿并排可读，长名受宽度约束 | 仍需顶部摘要，不能仅靠侧轨 |
| 暂停后分析指令 | 一个右抽屉，纵向阅读 | 下方统一工作区，视线集中 | 固定详情区，连续检查方便 |
| 跟随飞机／军舰／岸炮 | 默认不扰动，按需查详情 | 低空与舰体可能贴近底栏 | 长时看单位方便，但画幅变窄 |
| 720p 的主要风险 | 摘要省略与右侧遮挡 | 三段竞争宽度、展开吃高度 | 面板与导航轨压缩世界宽度 |
| 现有 Godot 接入成本 | 中；保留叠加 HUD 与相机接口 | 中；需底部展开和多行布局 | 中至高；预留世界区域时涉及相机／坐标换算 |
| 最匹配的观看习惯 | 自动电影为主、偶尔追查 | 经常暂停、集中读态势 | 长期选定对象、反复看详情 |

推荐外围轻 HUD，因为项目首版重点是电影化观赏，用户最需要先看到舰机的动作，再追查任务原因。它保留双方高层任务的必要存在感，减少默认遮挡，并能用现有动作路由和一个共享抽屉完成迁移。

三种方向最终都应使用主方案中相同的模态、真实数据、域适配、重开与输入规则。可以根据后续视觉反馈调整布局，不能混合三个方向的所有常驻入口，否则会重新形成当前的工具栏和多卡片堆积。
