# 统一视觉目标与 AI 参考图制作

更新：2026-11-10。资料包采用 **原始资料约束 → Image Gen 目标图 → Godot 粗模与统一视图 → 简化模型交付**。原始资料约束身份和结构，生成图表达本游戏的取舍与画风，Godot 渲染验证实际模型及视角一致性。

当前风格为 `simplified-historical-v0.2`：用户已认可 [SB2C-4 v04](references/bombers/sb2c/target/sb2c4-outer-form-candidate-v04.png) 的外观大形与简化程度，作为跨单位风格基准；这不表示图中每个尺寸、安装与标识已经通过历史校验。使用[参考图规范](standards/modeling-references.md)和[单位名单](unit-roster.md)，不扩展首版细节范围。

## 1. 全项目共用风格

| 项目 | 统一目标 |
| --- | --- |
| 整体 | 克制的简化半写实三维；真实轮廓与比例，画面干净、交战动作易读 |
| 几何 | 保留机身、机翼、舰体、建筑、主武器等大形；曲面适度平滑，不刻意做碎三角面或夸大成玩具比例 |
| 材质 | 大色面、哑光漆、少量金属高光；玻璃以深色面与必要框架表达；限制材质种类 |
| 细节 | 保留影响型号辨识、挂载、安装及运动的部件；省略铆钉、细孔、细密线缆、复杂内部、密集面板线与做旧 |
| 色彩 | 克制饱和度和表面噪声；各单位保留有依据的涂装差别，不把双方都改成同一颜色 |
| 参考展示 | 中性光、浅灰背景、完整全身、清楚轮廓；不以烟雾、景深、强轮廓光掩盖形体 |
| 游戏表现 | 镜头、运动、齐射、水花和声音营造电影感；风格图不承担游戏性能证明 |

风格规则与样图配套使用。后续单位使用同一版规则和风格参考；当前生成样图中的机型结构、标识和画面阴影不会自动成为其他单位必须复制的内容。

用户所说的“造型还原”指主要外轮廓、比例、曲率、体量和部件位置。飞机的机身与机头保持连续简洁外壳，不单独表现发动机罩的环、缝、开口和机械；座舱盖保留弧形外观，只用少量平面框线表达分段；起落架只保留轮子和简单支杆。武器保留可辨的外形、数量、位置与合理连接，不要求内部或完整机械复刻。军舰相应保留舰体曲线、上层建筑层次、烟囱和主要武器轮廓，收敛甲板小件、表面刻线、索具与机构。不能把“简化”理解为把真实轮廓改成通用方块或粗糙多面体。

军舰补充硬性约束：舰体与上层建筑的外观形状按所选舰名和日期对照一致，主炮、副炮的编制和位置必须完全符合。专用防空炮数量可以按游戏需求另行规划，具体范围和高平两用炮归类见[军舰规范](standards/ship-modeling.md)。AI 图中错误的建筑体量、主副炮移位或增减均为待修偏差，不能写成主动简化；只有防空游戏配置允许记录明确的数量差异。

## 2. 每型资料包怎么创建

| 步骤 | 执行内容 | 产物／检查 |
| --- | --- | --- |
| 1 锁定型号 | 舰名与年份或飞机子型；关键尺寸、主要装备、必要运动与展示状态 | 简短结构约束表，确定项与估值分开 |
| 2 精选原始参考 | 实际查看能解释大形的互补照片，必要时用手册／尺寸表补约束 | 原图与来源台账；按问题记录覆盖，不为凑数量搜无关图 |
| 3 生成风格主图 | 输入本型原图、结构约束、全局风格规则；已有风格样图另标“只参考风格” | 先做一张完整斜前或斜后目标图，通常沿用原图视角 |
| 4 对照核图 | 将生成图回查原始资料：轮廓、比例、部件数量、位置、子型特征和连接 | 风格可用／几何待核分开记录；按具体错误定向修改 |
| 5 制作 Godot 粗模 | 用历史尺寸和结构做主体；用合格目标图指导细节取舍、材质与颜色 | 从同一个粗模导出侧、前、俯、斜视，保证视图来自同一几何 |
| 6 补目标视图 | 必要时给粗模截图做受约束的 Image Gen 外观处理，始终保留原始资料和粗模输入 | 逐张核形体；处理后图仍是外观目标，几何以实际粗模为准 |
| 7 建模交付 | 按原始约束和目标图完成模型，对照中性截图及正常观战距离 | 大形、安装、运动、画风与性能分别验证 |

已有模型可从第 5 步的当前粗模开始，用 Image Gen 探索外观；不为走一遍流程重新建模。全新型号可先生成风格主图再做粗模。具体资料不足的隐藏面记录为近似范围，不靠生成图把未知项变成确定史实。

## 3. Image Gen 的输入和提示词

输入图片要分别标明用途：本型侧面／高位照片约束形状；另一角度补充结构；全局样图只约束材质和简化程度；Godot 截图约束当轮相机、姿态和已有轮廓。不给生成器一堆未筛选、不同子型的图自行混合。

每次提示词分成五段，下一单位复用风格段，替换型号段：

```text
用途：用于 Godot 简化历史海空战游戏的建模目标图。
输入：逐张说明型号照片、结构辅助、风格参考和粗模截图的角色。
结构约束：具体子型；关键比例、主要部件及数量；展示状态；必须保留的轮廓和安装位置。
统一风格：简化半写实；大色面、哑光、少量材质；无密集面板线、铆钉和做旧；必要曲面平滑。
输出：完整单体、明确视角、中性光与浅灰背景；沿用目标姿态；不增加装备、虚构支撑或装饰。
```

每轮只集中纠正一个明确问题，并再次携带原始约束。不要连续只拿上一张生成图继续生成，否则原始资料在后续输入中会丢失。对照记录说明哪些改变是主动简化、哪些是未接受的偏差。

## 4. 多角度与风格统一

每型通常先有 **1 张风格主图＋2–3 张必要的补充目标视图**。多角度生成图用于表达外观意图，不当作可量尺寸的工程三视图。一张拼合板中的侧视、前视、俯视也要逐个核对，不能因排在同一张图上就视为结构一致。

可靠的多角度几何基准来自同一个 Godot 粗模。Image Gen 在这些视图上的外观处理需要再次核图；发现改动机翼位置、炮塔数量或连接关系时，不回写成模型事实。细节简化、色块和材质可以采纳，关键结构仍回查尺寸表、原图和粗模。

跨单位统一依赖三项一起传递：**同一风格规则版本、同一组已选风格样图、相同的中性检视条件**。不要只重复“低模”“电影感”等宽泛词，也不要求军舰、飞机和武器共享相同轮廓或涂装。

## 5. 文件与交接

在已有型号参考目录中增设 `target/`，原始资料保留原位置，不覆盖：

```text
型号目录/
  modeling-brief.md          # 本型约束、精选参考、目标图用途和缺口
  sources.json              # 原始资料来源
  原有照片或 images/         # 未修改的原始参考
  target/
    style-candidate-v01.png # AI 风格目标候选
    style-candidate-v01-prompt.md  # 输入、实际提示词、版本和图像检查
  checks/                   # 后续 Godot 同模型多角度截图与对照
```

选中的生成图保存到项目目录。每张目标图带状态和适用范围，例如“材质与简化程度可用，座舱形体待核”；原始资料、生成目标图、Godot 实际渲染不得混称。常规生成、核对和整理由 Codex 完成，不新增逐图用户审批。
